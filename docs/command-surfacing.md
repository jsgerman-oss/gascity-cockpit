# Command surfacing audit

> Status: **BUILT** (cockpit-dc8.3). Audited 2026-06-06 against `main` after the
> feature wave (chat, beads operational toggle, telemetry, time-travel, …).
> Re-run the analysis any time a feature adds a command — the goal is that no
> *user-facing action* lives only in the command palette.

Every command the Cockpit contributes should be reachable from a visible
affordance — a view-title button, a row context menu, an editor right-click, a
status-bar item, or a code lens — not just the `⌘⇧P` palette, which a user only
finds if they already know the command's name. This is the discoverability audit
of the manifest plus the wiring that closes the gaps.

It is **not** a mandate to put every command on a button. Diagnostics and
advanced power actions are *correctly* palette-only — a button for them is
clutter. The audit's job is to separate *buried* (a normal action with no
non-palette entry) from *appropriately palette-only* (a diagnostic/advanced
action), and to wire only the former.

## How to read "current entry point"

Affordances come from each feature's `src/features/<id>.contributes.json` and the
core's `src/host/host.ts`. A command appears in the **command palette by
default**; the table notes palette presence only where it is the *sole* entry, or
where the feature explicitly hides it (`commandPalette` → `when: false`) because
the command is row/lens-scoped and meaningless without its target. Menu order is
by `group@order`, so the activity-bar buttons read left-to-right by their
`navigation@N`.

now wired as Fleet view-title buttons — no new panes, reusing the existing
toolbar per the feature-registry convention (each lands in its own feature's

Both also remain in the palette (the standard pattern — every other view-title

## The four candidates from the bead

The bead named four candidates to "verify against current main". Two were real
gaps (wired above); two were already satisfied and are deliberately left alone:

- **`fleetQuery.open` → Fleet view-title button.** ✅ Wired. It queries the whole
  fleet, so the Fleet view is its home. Already carried a `$(search)` icon.
- **`openDashboard` → view-title button (Fleet or Events).** ✅ Wired to **Fleet**.
  It projects the *fleet-wide* web dashboard (`docs/dashboard-embed-contract.md`),
  so Fleet — the flagship live view — is the natural home; the Event Feed would
  read as arbitrary. Added a `$(dashboard)` icon (view-title buttons render as
  icons).
- **`beads.newFromSelection` → editor/context, `when editorHasSelection`.**
  ⏭️ Already in the editor right-click menu (`when: editorTextFocus`) — **kept as
  is.** `captureSelection` in `src/views/newBeadFromSelection.ts` *deliberately*
  falls back to the caret's whole line when nothing is selected, and the prompt
  reads "put the cursor in **(or select)** the code". Gating on
  `editorHasSelection` would hide a path the feature intentionally supports, so
  `editorTextFocus` is the correct condition.
- **Connection status-bar item (reachability + click-to-reconnect).**
  ⏭️ Already built in `src/host/host.ts` — **no change.** The host creates an
  always-visible status-bar item that renders reachability by state (icon, label,
  and warning/error background for `reconnecting`/`unavailable`), with a tooltip
  showing the endpoint and server build. Its click runs **Show Connection
  Status**, whose dialog offers **Reconnect**. The deeper typed-`/v0` probe
  (`checkConnection`) stays a palette diagnostic.

## Adding a command later — the rule

When a feature adds a command, give it a non-palette home in the *same*
`*.contributes.json` unless it is a diagnostic or an advanced power action. The
homes, in order of preference:

1. **A row/item action** if it operates on a tree item → `view/item/context`
   (and hide it from the palette with `commandPalette` → `when: false`).
2. **A view-title button** if it is a view-scoped global action → `view/title`,
   `navigation@N`, with an `icon`.
3. **An editor right-click** if it acts on the active editor → `editor/context`.
4. **A status-bar item / code lens** for ambient or in-file actions (in glue).
5. **Palette-only** *only* for diagnostics and advanced power actions.

Then `npm run sync:contributes` and `npm run check` (the drift guard in
`src/features/contributes.test.ts` fails if `package.json` is stale).
